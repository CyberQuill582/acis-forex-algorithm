## A. Contradictions between sources

### F1 — NVMA loop cadence disagreement · NOTED (resolved)
- **Evidence:** S1 §3.2 "NVMA runs on a 1–5 minute cycle"; S1 §4 loop 2 "60s–300s"; **S2** loop card "MEDIUM LOOP 1–15min". Three different upper bounds.
- **Resolution:** L §4/§10 uses **60–300 s** (matches S1, the authoritative source). S2's 15 min is the outlier and is retired.
- **Guard:** deep spec `ACIS-02` locks the cadence to the `system_config` value with 60–300 s bounds; the medium loop's heartbeat SLA (§12) must be consistent with the chosen cadence.

### F2 — Correlation-cluster set contradicts *within* S1 · NOTED (resolved)
- **Evidence:** S1 §3.5 prose lists 5 clusters incl. `GOLD_PROXY` and no `commodity`/`yen_carry`; S1 §5 YAML lists 6 — `usd_long, usd_short, commodity, yen_carry, risk_on, risk_off` (no `GOLD_PROXY`). Same document, two cluster sets.
- **Resolution:** L §6/§9 adopts the S1 §5 YAML set (6 clusters). `GOLD_PROXY` is subsumed by `commodity`/`risk_off`.
- **Guard:** `ACIS-05` Governor spec + `instruments.yaml` fix the 6-cluster set as canonical; see **F12/C7** for the extension-instrument reference issue.

### F3 — QIEA promotion trigger: "session boundary only" vs "position close OR boundary" · FIXED (C2) + OPEN residue
- **Evidence:** L §2 conflict table + S1 §3.3 "promoted at the next valid session boundary"; **S2** arbitration table row 2 "Deployed at next position close **or** session boundary." Sources disagree on whether a position *close* can trigger promotion.
- **Resolution (C2):** adopt the **stricter** rule — promotion only at a session boundary with `open_positions == 0`; position-close is **not** a trigger. This is safer (a mid-session close still leaves other positions/params entangled) and matches the "never mid-session" invariant.
- **Residue (liveness):** the strict rule can starve promotion indefinitely (F8). Handled by making staleness observable, not by weakening the rule. See F8.

### F4 — Conviction scale 0–1 vs 0–100 · FIXED (C4, scale clause) 
- **Evidence:** S2 says "conviction score (0–100)" in the layer-4 card and Governor prose, but "ConvictionScore(0–1)" in the formula block. S1 + L use 0–1 throughout.
- **Resolution (C4):** 0–1 is canonical everywhere; the 0–100 phrasing is retired. Recorded in L §5.5.

### F5 — Governor soft throttles present in S2, absent in L · split FIXED (C3) / OPEN
- **Evidence:** S2 Governor formula block + guardrail cards carry three soft rules not in L §6:
  1. `IF RegimeHalfLife < SessionHorizon → PositionSize × 0.5`
  2. `IF LiquidityScore < THRESHOLD → PositionSize × 0.25` (S2) / `× 0.10` on slippage (S2 "Liquidity Floor")
  3. `IF DrawdownToLimit < 0.20 → PositionSize = 0` (pre-limit buffer)
- **Resolution:**
  - (1) → **C3 (FIXED as decision):** half-life kept advisory; not a separate throttle, to avoid double-counting regime quality already in `regime_stability × regime_confidence`. Promotion to a real factor is **OPEN — deep spec** (`ACIS-05`).
  - (2) slippage auto-throttle → **OPEN — human decision** (F10): sizing/guardrail semantics.
  - (3) drawdown pre-limit buffer → **OPEN — human decision** (F9): HALT semantics.

## B. Latent logic flaws (single-source or emergent)

### F6 — "session boundary" was undefined but load-bearing · FIXED (C1)
- **Flaw:** the entire QIEA safety rule, `MarketState.session`, and the "next valid session boundary" promotion trigger all depend on "session boundary", which no source defines. Forex trades 24/5 — without a definition the rule is unimplementable and untestable.
- **Resolution (C1):** L §5 now defines it as an explicit `system_config.yaml` `session_boundaries_utc` list (default 22:00 UTC daily rollover + London/NY/Tokyo opens); single source of truth; empty/bad list = fatal at startup.
- **Guard:** `ACIS-03` §State-machine + `ACIS-01` §session-tagging must both resolve against this one list; DST handling is a named glitch test (S1/L §13).

### F7 — `estimated_half_life_seconds` emitted but never consumed · FIXED (C3)
- **Flaw:** `RegimeContext` (L §4) carries `estimated_half_life_seconds`; no downstream layer reads it. Either a dead field or a missing consumer (S2 intended it as a `×0.5` throttle — see F5.1).
- **Resolution (C3):** declared advisory — logged + exposed on `acis://regime/current`, deliberately not a sizing factor. Kept because it is a useful observability signal and a candidate future factor. Not dead; disposition is explicit.

### F8 — QIEA promotion liveness / deadlock · FIXED (C2, observability) + OPEN (policy)
- **Flaw:** with the strict F3 rule, if a position always straddles boundaries, staged params never promote → unbounded staleness, silently.
- **Resolution (C2):** staged params carry `staged_at` + `boundaries_skipped`; each skipped boundary logs `PARAM_PROMOTION_STALLED` and, past `param_stall_alert_boundaries` (default 3), surfaces on `acis://params/pending`. Safety rule unchanged; the *deadlock is now visible* so a human/orchestrator can act (e.g. schedule a flat window).
- **OPEN — human decision:** whether a prolonged stall should *force* a flat-and-promote window is a policy/guardrail question, not an agent's to decide.

### F9 — Drawdown acts only *at* the limit, no pre-limit buffer · OPEN — human decision
- **Flaw/where sources differ:** S2 guardrail "IF DrawdownToLimit < 0.20 → PositionSize = 0" stops opening when *within 20 % of* the daily drawdown limit; L §6/§8 only zeroes at/after the limit is breached. The buffer is strictly safer (stops before the wall) but changes when trading halts.
- **Why OPEN:** this is HALT/sizing semantics governed by `config/guardrail_limits.yaml` and CLAUDE.md's "never touch without a human" rule. An agent may not add or remove a halt trigger.
- **Recommendation to human:** adopt the buffer as a *soft* pre-halt taper (e.g. linear size taper as daily drawdown approaches the limit) rather than a hard cliff at 80 %, so it reduces risk without a surprise stop. Ratify in `guardrail_limits.yaml` + `ACIS-05`/`ACIS-07`.

### F10 — Slippage breach alerts only; no auto-throttle · OPEN — human decision
- **Flaw/where sources differ:** S2 "Liquidity Floor" card auto-cuts an instrument's allocation (`× 0.10`) and prefers dark routing on slippage breach; L §8 emits `slippage_slope_alert` at 8 bps but specifies no automatic size response.
- **Why OPEN:** an automatic allocation cut is a sizing/guardrail action. Also, "dark pool" routing is not meaningful in retail forex (no lit/dark venues the same way) — that half of S2's rule should be dropped regardless.
- **Recommendation to human:** keep the alert; add an optional, config-gated per-instrument slippage throttle in `ACIS-06`/`ACIS-07` (ratified value in `guardrail_limits.yaml`). Drop dark-pool language.

### F11 — Conviction discount vs discard-threshold ordering · FIXED (C4)
- **Flaw:** L/S1 apply a `×0.85` MEDIUM-volatility discount *and* a `< 0.45` discard cut, but never state the order. A raw 0.50 signal passes if thresholded first, fails if discounted first — a real behavioural fork.
- **Resolution (C4):** discount first, then discard against the post-discount value. Locked in L §5.5; `ACIS-04` must unit-test both orderings and assert the discount-first outcome.

### F12 — Clusters reference non-default (extension) instruments · FIXED (C7)
- **Flaw:** `commodity`/`risk_off` clusters list `XAUUSD_L`, but XAU/USD is an "extension when mature" instrument (L §9), not in the default majors/minors. A naïve loader could silently ignore it.
- **Resolution (C7):** cluster membership may reference extension symbols; they are inert until the instrument is enabled in `instruments.yaml`; a cluster referencing an *unknown* (never-defined) symbol is a config error, not a silent drop. Also clarified: clusters are **fixed membership lists**, and the "real-time correlation tracker" measures exposure *within* a cluster — it does not compute membership live (a common misreading of S1/S2).

### F13 — Alpha-decay baseline window ill-defined below 200 trades · FIXED (C5)
- **Flaw:** S1 §3.7 `detect_alpha_decay` compares Sharpe(last 50) to Sharpe(`trades[-200:-50]`) with a `len < 30` guard. But the *baseline* window needs its own minimum; with 30–200 trades the baseline is truncated/near-empty and its Sharpe can be undefined (divide-by-tiny-σ), producing spurious flags or NaN.
- **Resolution (C5):** baseline requires `alpha_decay_baseline_min_trades` (default 50) present in `[-200:-50]`; below that the comparison is inactive and the warming state is surfaced on `acis://risk/snapshot` so "insufficient data" is never read as "no decay." `ACIS-07` owns the NaN-safe Sharpe.

### F14 — Marginal-alpha normalisation undefined · FIXED (C6, as contract) + OPEN — deep spec
- **Flaw:** S1's `compute_marginal_alpha_coefficient` returns `0.25` when `marginal ≤ 0` else `min(marginal_normalised, 1.5)`, but `size_delta` and `marginal_normalised` are never defined — the map from a raw derivative (units: alpha per unit capital) to a `[0.25, 1.5]` multiplier is missing.
- **Resolution (C6):** L §6 makes the normalisation a *contract* (bounded `[0.25,1.5]`, monotonic non-decreasing, `0.25` for marginal ≤ 0, `1.0` at neutral, NaN-safe, pinned to `1.0` until `marginal_alpha_min_trades`). The *exact function* is **OPEN — deep spec** `ACIS-05` (must be specified + unit-tested against those properties).

### F15 — Size-bucketing for marginal alpha is circular / cold-start · OPEN — deep spec
- **Flaw:** marginal alpha compares "alpha at small size" vs "alpha at large size" from rolling 50-trade buckets — but the Governor *controls* size, so buckets only populate if the Governor has already varied size, and are empty at cold start. Risk of a self-referential estimator that never leaves its initial regime.
- **Resolution:** `ACIS-05` must define the cold-start (pin to 1.0), the size-bucket boundaries (relative to `BASE_UNIT_USD`), and an exploration policy or fallback so buckets populate. Flagged as a `C`-correction in that deep spec.

### F16 — `raw` payload in a frozen dataclass · OPEN — deep spec (NOTED severity: low)
- **Flaw:** `MarketState.raw: Dict` is inside a `@dataclass(frozen=True)`; a dict is mutable, so "frozen" is shallow — a consumer can mutate `raw` and violate the immutability contract the layer law relies on (L §2 "consumers never mutate producer state").
- **Resolution:** `ACIS-01` must store `raw` as an immutable mapping (e.g. `MappingProxyType` / deep-frozen) or a serialized blob, and the frozen-dataclass immutability test must assert deep immutability, not just attribute reassignment.

### F17 — Float PnL vs Decimal boundary · NOTED (covered) 
- **Evidence:** L §13 already names "float accumulation drift in PnL (use Decimal at accounting boundaries)" as a glitch class. No contradiction — recorded here so `ACIS-07`/`ACIS-09` treat Decimal at accounting boundaries as binding, not optional, and so the next pass checks it is actually specified per-field (which fields are Decimal vs float).

### F18 — Session median needs a warm-up definition · OPEN — deep spec (NOTED)
- **Flaw:** NVMA veto uses "spread > 3× session median" and "tick velocity < 0.5× session median"; the Governor/monitor use session-relative baselines. "Session median" needs a defined estimation window and a cold-start value (first ticks of a session have no median). Undefined → first-N-ticks-of-session behaviour is ambiguous.
- **Resolution:** `ACIS-02` defines the session-median estimator (rolling window, minimum sample, cold-start fallback = treat as untradeable until warm). Ties to the DST/Sunday-open glitch tests.

## Pass 2026-07-14 — money-viability & governance audit (F19–F24)

**Pass date:** 2026-07-14 · **Auditor:** pre-build adversarial pass (human-directed) · **Master spec at audit:** `ACIS_SPEC.md` v2.2 → v2.3

**Scope of this pass** (distinct from the v2.1 cross-source reconciliation above): an adversarial read for **money-losing flaws, self-contradiction, and drift risk** before code is written — "an engine that can make money, not a joke" — plus the governance-philosophy hardening applied family-wide (guard-integrity + untrusted-input; the subordinate-model adversarial-audit workflow in `CLAUDE.md`). Trading findings are backed by July-2026 external research (transaction-cost realism, win-rate-vs-expectancy, prop-firm risk rules, news-blackout norms, overfitting discipline). **No guardrail, HALT, veto, equity-floor, sizing-limit, or QIEA-no-mid-session semantics were changed; guardrail-adjacent findings are raised, not applied.**

### F19 — QIEA fitness may optimise on gross (frictionless) returns · FIXED (C8)
- **Flaw:** §5 / `ACIS-03` fitness is a "mini-backtest over 500 bars" that never states costs are netted, while `ACIS-09` *does* model spread + slippage (C-BT-5). Optimising gross while validating net is the classic backtest lie: QIEA would select params profitable only without spread/commission/swap, which then die live.
- **Resolution (C8):** fitness must apply the **same** cost model as the `ACIS-09` backtest, unit-tested identical in both. Applied inline in §5. Strengthens honesty; weakens no guard. Deep-spec `ACIS-03`/`ACIS-09` own the shared model.

### F20 — win-rate-in-isolation trap; expectancy not first-class · FIXED (C9) + OPEN (deep spec)
- **Flaw / owner tension:** the owner asked to "maximise win rate." Research is unambiguous that win rate alone is misleading — a 90%-win system with poor R:R is negative-expectancy; profitable trend systems win only 35–48%. Nothing in the spec made **expectancy** the objective; win rate carried a 0.20 fitness weight and a §14 target with no expectancy gate binding them.
- **Resolution (C9):** positive net expectancy `E = winRate·avgWin − lossRate·avgLoss` (costs included) is a **hard gate** — a ≤ 0 ParamSet cannot win evolution and a strategy cannot hold a rung on it; win rate is a component, never the objective, and is never quoted without its realised R:R. §14 keeps *both* win rate > 48% and PF > 1.4. Applied in §5/§5.6. **OPEN — deep spec:** the exact expectancy normalisation function (`ACIS-03`, like the C6 contract).

### F21 — Momentum-Scalp horizon contradicts the avg-duration target · OPEN — human decision
- **Flaw:** §5.5 / `ACIS-04` Momentum Scalp runs a 5–15 **bar** horizon on the FAST loop (tick–5s ⇒ seconds–minutes), but §14 sets an **average trade duration floor of 30 min–48 h**. Scalps are also ~1:1 R:R (cost-sensitive, ties to F19) and sit uneasily against §17's "not HFT." Either "bar" means a coarser timeframe than the fast-loop tick, or the scalp module structurally violates the duration target, or scalp trades must be carved out of that metric.
- **Why OPEN:** this is strategy-scope / performance-target semantics. **Recommendation to human:** define the Momentum-Scalp bar granularity explicitly in `ACIS-04`, and either (a) exclude scalp trades from the §14 avg-duration metric with a stated rationale, or (b) drop the module if it cannot clear expectancy net of cost at its horizon. Do not silently resolve.

### F22 — decisiveness vs analysis-paralysis · FIXED as principle + OPEN (deep spec) for the budget
- **Flaw:** NVMA regime context is up to 300 s old on the fast loop, and the layered vetoes + conviction discounts + `ambiguity = no trade` can be tuned so conservative the engine structurally never trades — which the Final Mandate already calls failure ("loses no money and makes no money has failed"). There was no stated decisiveness obligation or starvation signal.
- **Resolution:** §10 gains a **decisiveness (anti-paralysis) rule** — a bounded decision-latency budget with all vetoes/HALTs still sovereign, plus a signals-considered / trades-taken take-rate on `acis://status` so starvation is a reportable health condition. **OPEN — deep spec:** the concrete `fast_loop_decision_budget_ms` value (`ACIS-04`).

### F23 — overfitting surface: ~11 genes over a 500-bar window · OPEN — deep spec
- **Flaw:** `ParamSet` evolves ~11 genes; research favours < 5 parameters, ≥ 20% held-out OOS, walk-forward across regimes, and robustness plateaus. §5.6 mitigates (attempt registry, ±10% plateau, rung ladder), but the 500-bar fitness window is thin and QIEA itself OOS-validates only at the final `ACIS-09` backtest — a self-referential estimator can look good in-window and fail forward.
- **Why OPEN:** touches fitness semantics. **Recommendation:** `ACIS-03` sets a fitness-window minimum (or a held-out split inside the window) and requires cross-regime out-of-sample validation of a promoted param set before it can reach live — not only the final backtest gate.

### F24 — trusted-news channel guidance was abstract · FIXED (additive)
- **Flaw:** §3.5's trusted-channel design is sound but named no channels or event taxonomy, leaving "trusted" underspecified for the future `event_sources.yaml` author.
- **Resolution:** §3.5 now names reputable calendars as **examples only** (Forex Factory, FXStreet, Trading Economics API), the Tier-1 taxonomy (NFP, CPI, FOMC / rate decisions, GDP), and the observed ~2–5 min prop blackout reality — human-config-commit stays binding, and the new untrusted-input law fences the headline feed. Additive guidance; no guard changed.

## Pass 2026-07-15 — any-account / any-instrument capability audit (F25–F31)

**Pass date:** 2026-07-15 · **Auditor:** capability-expansion pass (human-directed) · **Master spec at audit:** `ACIS_SPEC.md` v2.3 → v2.4

**Scope:** the owner's mandate read adversarially against v2.3 — *"serious results on a personally funded account or a prop firm; any account it's given, XAUUSD, futures, currency pairs; all relevant news including geopolitics; quick connection to platforms; rigged for evolution; neither analysis-paralysis nor an account-blower."* Each finding is a place where v2.3 structurally could not deliver that mandate. **No existing guardrail, HALT, veto, equity-floor, sizing-limit, or QIEA-no-mid-session semantics changed; guardrail-adjacent numbers raised, not applied.**

### F25 — single-asset assumption: the spec was forex-shaped at the bone · FIXED (C10)
- **Flaw:** "forex trading engine" throughout; C1 session boundaries hardcoded to the forex rollover + city opens; instrument universe a fixed FX list with XAU/WTI/futures as vague "extensions"; no contract metadata (tick value, contract step, expiry), no market calendars, no futures lifecycle. An XAUUSD-only prop account — a completely ordinary owner scenario — was unimplementable without ad-hoc code branches.
- **Resolution (C10):** §3.7 asset-class law — instrument-specific behaviour is declared data (contract metadata + market calendar per instrument in `instruments.yaml`); C1 generalised per-calendar with the forex default preserved; futures first-class (roll windows, continuous-contract stitch, limit-lock = ILLIQUID); incomplete metadata = attach-time fatal. §14 evaluated per attached account.

### F26 — prop accounts die by rules the spec never modelled · FIXED (C11) + OPEN (buffer fraction)
- **Flaw:** `platform_rules.yaml` covered news restrictions well, but prop accounts are killed by *trailing* drawdown anchored to intraday high-water equity, consistency rules, min trading days, weekend bans — none modelled. ACIS measuring its own 2% daily drawdown while the platform measures a trailing intraday limit is exactly how a "safe" engine fails an account.
- **Resolution (C11):** §9.5 account doctrine — stricter-of law; platform drawdown tracked under the *platform's* measurement semantics as a first-class RiskSnapshot series; rule categories as Governor hard overrides; consistency = eligibility, never pressure; strategies whose horizon violates min-hold are ineligible on that account. Only ever adds constraints. **OPEN — human decision (GAP-0010):** the pre-limit buffer fraction (act at X% of the platform limit) is HALT/sizing semantics — extends F9/GAP-0003.

### F27 — event picture blind to the unscheduled world · FIXED (C12) + OPEN (auto-flatten)
- **Flaw:** §3.5 handled scheduled releases and a vetted headline feed, but had no taxonomy for wars, ceasefires, sanctions, trade deals, elections, supply shocks — the owner's explicit "wars and deals" trend-changers. Nothing structural stopped a future implementer from wiring headlines into direction, either.
- **Resolution (C12):** §3.6 Tier-G taxonomy (deterministic keyword classes → affected-instrument maps in `event_sources.yaml`) + the **shock-asymmetry law**: in-loop, unscheduled news can only make ACIS more conservative (vol class up, veto, shock fraction) — never a direction or size-up; the nuanced narrative lane is out-of-band (`geopolitical-brief`) landing as staged config only. Untrusted-input law extended. **OPEN — human decision (GAP-0011):** whether a Tier-G shock may auto-*flatten* open positions on affected instruments (a HALT-semantics addition) or only veto new entries as now specified.

### F28 — connectivity hardcoded; adding a platform meant editing core · FIXED (C13)
- **Flaw:** §3 named OANDA/MT5/IBKR as connectors with no contract; nothing defined order-type capabilities, netting-vs-hedging, symbol maps, or how a new platform (cTrader/DXtrade/TradeLocker/Match-Trader — the actual prop-firm spread — or a futures gateway) attaches. "Quick connection to various platforms" was impossible without touching core layers each time.
